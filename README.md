# 椿萱常伴——桌宠驱动的适老化关怀助手

让老人更容易安排与记录日常，让家属的关心更具体。

椿萱常伴面向居家老人与家属，将适老化交互、家庭授权协作、活动桌宠和七日智能分析连接起来。老人通过分步问答创建安排并自主确认完成，家属在绑定家庭内协助维护日程、查看进展和发送提醒。

日常安排与家庭协作采用规则流程；**七日生活洞察与七日关怀研报**由用户主动触发，先由程序整理授权记录，再由语言模型组织观察、分析、鼓励和行动建议，并提供可展开的记录依据。

快速体验无需注册，顶部可以切换同一虚拟家庭的老人端和家属端，也可以选择不同情境：

| 情境 | 记录内容 | 推荐体验 |
| --- | --- | --- |
| 日常协作 | 七天日程样例及当天生活记录 | 日程创建、完成反馈与家属提醒 |
| 七日规律生活 | 完整七天日程、睡眠和心情记录 | 七日观察、鼓励与依据展示 |
| 七日作息变化 | 完整七天记录，包含作息与心情变化线索 | 趋势解释及角色化关怀建议 |

默认进入“七日规律生活”。快速体验采用虚拟数据与基础解读，正式账号配置模型后可主动生成 AI 分析。体验修改保存在当前页面，刷新或确认重置后恢复样例；跨设备协作请使用正式账号并完成家庭绑定。

### 推荐体验顺序

1. 在老人端完成一项日常，同页切换家属端查看进度。
2. 双击桌宠打开面板，通过分步问答创建安排，选择频率、日期、时间与可选备注，核对后保存。
3. 对已到时间且尚未记录完成的事项发送家属提醒，切回老人端点击“知道了”，查看对应回执。
4. 打开“历史”，查看七天图表，点击日期核对明细。
5. 选择“七日作息变化”，从历史页或桌宠进入七日分析，主动生成报告并展开记录依据。
6. 在顶栏“桌宠”设置中切换形象，体验自由活动、固定位置和陪伴偏好。

## 核心功能与创新设计

### 双端授权协作

老人和家属分别使用独立角色账号，通过家庭码绑定。家属可协助安排、查看进度和发送提醒；日常完成由老人本人确认，生活记录的分享也由老人决定。

提醒的“收到回执”与日程的“完成记录”分别保存。同一事项设置提醒冷却，日程变化后过滤过时提醒，使反馈含义清晰。

### 适老化渐进交互

将日程创建拆分为“事项—频率—日期—时间—可选备注—核对保存”，每次只呈现当前问题。日期时间可直接选择，返回修改保留内容，最终确认前不保存，配合大字、清晰标签和较大的点击区域降低操作负担。

语音输入在主动同意后通过浏览器转写，识别文字需核对；文字与控件选择始终可用。语音播报默认关闭，开启后使用设备或浏览器提供的音色。

### 陪伴式桌宠入口

团团、慢慢和豆豆提供可切换的形象，支持自由活动、固定位置和互动偏好。桌宠连接提醒、操作反馈与功能面板，按老人和家属身份展示不同内容。

桌宠在网页内活动，形象动画与业务逻辑分离，便于扩展外观。

### 历史可视化与生活记录

七天图表区分已完成、到时未记录和时间未到，点击日期进入明细；近七天与近三十天汇总支持逐日回看。历史由计划版本和每日执行还原，后来编辑或停用不会直接覆盖过往解释。

老人可记录心情、睡眠、可选血压与文字备注，家属在获得分享授权后查看。记录不全、没有安排和未确认完成分别说明，避免将缺失信息解释为零完成或现实中未执行。

### 有依据的七日智能分析

分析范围为北京时间今天及此前六天：

```text
授权筛选 → 七日事实计算 → 模型组织分析 → 输出校验 → 报告与依据展示
```

| 输出 | 表达重点 |
| --- | --- |
| 老人端：七日生活洞察 | 肯定具体努力，理解生活节奏，提供轻量行动建议 |
| 家属端：七日关怀研报 | 解释变化线索，提供沟通方向和适度协助建议 |

程序计算日期、状态与聚合事实，模型组织表达。结构与引用校验检查依据标识、明显无来源数字和部分诊断性措辞；异常时提供明确标注的基础解读。分析不自动修改日程、确认完成或通知家人。

打开分析界面只读取记录，点击同意生成后才请求模型。请求仅携带选定范围的角色、日期与聚合事实，不自动上传姓名、电话、家庭码、日程标题、文字备注或血压。家属只能纳入获得授权的生活记录。实现细节见[七日洞察说明](docs/七日洞察说明.md)。

## 本地运行

需要 **Node.js 22.13 或更新版本**，推荐 Node.js 24，以及 npm。下载并解压源码或克隆仓库，在包含 `package.json` 的项目目录打开终端：

```sh
npm install
npm run demo
```

启动成功后访问：

- 老人端体验：<http://127.0.0.1:3000/?demo=elder>
- 家属端体验：<http://127.0.0.1:3000/?demo=caregiver>
- 账号入口：<http://127.0.0.1:3000/>

Windows CMD 可用 `cd /d "你的项目目录"` 切换目录；PowerShell 使用 `Set-Location "你的项目目录"`。运行期间保持终端开启，按 `Ctrl+C` 停止。

启动器自动初始化本地 SQLite，数据保存在被 Git 忽略的 `.data/`。服务监听回环地址，仅供本机访问。本地、Netlify 与 Sites 的账号和数据库彼此独立。

### 正式账号与家庭绑定

1. 注册老人账号，在“家人”中获取家庭码。
2. 注册家属账号，首次登录填写家庭码、称呼、联系方式和关系。
3. 双方在各自账号中查看同一家庭的授权信息。

普通浏览器标签页共享登录会话，同时测试两端可使用不同浏览器或普通／隐私窗口。快速体验支持同页切换角色，正式账号角色由服务端固定。

## AI 服务配置

规则日程、家庭协作与基础解读无需模型密钥。使用正式账号的 AI 分析时，将 `.env.example` 复制为 `.env.local`，填写以下服务端变量：

| 变量 | 作用 |
| --- | --- |
| `AI_API_KEY` | 服务商提供的访问密钥 |
| `AI_BASE_URL` | Chat Completions 兼容基础地址，不附加 `/chat/completions` |
| `AI_MODEL` | 服务商支持的模型标识，需要支持 JSON Object 输出 |
| `AI_DISABLE_THINKING` | 部分兼容模型的关闭思考选项，按服务配置 |

保存后重启本地服务。Netlify 在平台环境变量中配置同名参数，确保 Functions 可读取。真实密钥不写入源码、提交仓库或放入浏览器配置。

系统采用超时、输出长度和实例内账号频率限制，并提供基础解读回退。模型费用按服务商规则计算；实例内限流不等于全站费用上限。兼容参数与可选日程对话模块见 [AI 接入说明](docs/AI接入说明.md)，项目主要 AI 应用展示为七日分析与关怀建议。

## 使用范围

常伴用于生活安排与家庭关怀。未记录完成不代表实际未做，七日分析提供关怀参考，不作疾病诊断、心理测评结论或用药调整。

网页在应用运行期间提供站内提醒，联系请求和家属提醒不等于短信、电话或后台推送。语音能力取决于设备、权限与服务条件。在线访问受托管平台可用性和额度影响，源码同时提供本地运行方式。
